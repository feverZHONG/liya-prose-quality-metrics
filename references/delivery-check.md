# delivery-check · 从 SKILL.md 拆出（2026-09-22）

### 4 · 重量（＝交付前的**四件套**，缺一件不算改完）

① 量尺（四个数）② 扫雷 ③ 语气—标点复检 ④ **账核对**。**四件套要跑成一条命令、挂在提交上**（别靠记得）：把四项包成 `<tool> gate`，再挂 `.git/hooks/pre-commit` 只查暂存区动过的稿子，不过就拒提交；引擎级坑（CLI 退出码／暂存路径／装完必须实测）见 `skill: dev-workflow`「提交门禁」。前三件只看**句子形状**，没有一件看得出「内容在不在」；字数涨了还要看对话占比有没有被叙述稀释（**扩写最容易一边涨字数一边摊平**；**承接补／连续性修补尤其如此**——补进去的几乎全是叙述，几条就把占比压出区间，此时**别砍承接补**，先判**这套「多说的话」是不是这一节的设计**：**不是设计**（这节的对话本来就是主戏）→ 用「补一句讲本行的话」换回来（实测 38.1%→36.5% 的一节，补两句她的话回到 38.1%）；**是设计**（谷段她不说话／独飞段不设对话线）→ **登记成放宽项**，别为配额硬塞台词（实测谷段 36.3%→34.7%，判为设计后进放宽带）。补完立即重量）。

- **缺的那条先查出处，再决定「补回」还是「改账」**：骨架里的「台词」常是**大纲叙述句被第一人称化**的产物——出处原文是第三人称的方案说明（`莉娅在期待懂得欣赏艺术并愿意探索其背后故事的人`），被抄成台词（`我一直在等一个懂得欣赏…的人`）填进清单还标 ✅。这类**不是丢了台词**：人根本不会那么说话，补回去＝硬塞。**改账（记下它是叙述句）＋把那一拍落成动作**（她听见脚步／手里的笔停在半空），一举两得。判据：grep 出处文件（`raw/`／素材库／大纲），原文是叙述或方案语言 → 不写成台词。
- **反过来也成立：账上记了、正文 0 命中的短句，可能正是本轮要用的补丁。** 结构改动（加一拍抗拒／加一次外部确认）常常不需要新写——**骨架或人物状态里写着、正文里一个字都没有**的那类短句（一句「只给事实」的他、一句确认），落回去＝补齐写定口径，比新写安全、也不会踩红线。所以核对时遇到这类条目，**先问「它是不是本轮要用的料」，再判改账**。

**④ 账核对怎么跑**：拿这一节的骨架（大纲事件清单／节点细单／铺垫账／加厚单）**逐条 grep 正文字面**，报「清单里 N 条、正文里在 M 条」，缺的当场补回或改账。

- **顺序：动笔之前先校骨架，再写正文**（用户点「要调整的是大纲问题，所以写正文前先校对一遍」时就是这个动作）。每条账**三选一**，别混着改：**改正文**（正文与骨架不符：骨架标★的承重拍被写成别人代做）／**改账**（骨架自己写错：出处、落点、方向、口径——同一件事被记成了另一节收，或方向根本是反的）／**记账**（本节自立，无上游也不追）。实测十几节下来，翻出来的问题**几乎全在骨架层**，正文的句子病很少；骨架错了还往下写＝白写一遍。

- **只核「本节自己的承诺」**：只取骨架的**实施列**（铺垫账左列／事件清单）；「收在哪」那一列与承接账的上下游表写的是**别节**的事——不筛会给每节几十个假阳性（实测 86 → 9 个）。
- **清单措辞要能被逐条 grep**：注记别塞进 `（）`／`「」`（`（藤蔓底下）` 这类会让账核永远亮灯）。对不上时先判是**正文缺**还是**清单写法对不上**——清单自己写歪的**改清单，不改正文**。
- **抓词工具侧要过滤非承诺串**：行号引用（`L71–L77`）、纯数字、嵌套引号、表格表头与「收在哪」这类注记词都不是承诺——不过滤的话每节都亮一排假红灯，改到人麻。同理 `（）`／`「」` 里嵌 `「」` 要先剥层次再比。
- **账核对要能一条命令跑**：把「抠清单词 → 逐条 grep 正文」做成 CLI（本项目＝`bin/story gate` 的账核段）；人工每次现做＝和「靠记得」没区别。

- **为什么非跑不可**：改写会把整句台词掉包而不留痕——实测重写一节时「水面的光最难画（你画下去的时候它已经变了…）」整句丢了，而量尺（字数、四项体检全绿）、扫雷、语气标点**三件全过**，大纲里那一拍还记着 ✅；同款病灶在别节也抓到（一句动机台词正文 0 命中、大纲记 ✅）。**字数对得上 ≠ 内容都在**（掉一句台词、补一句叙述，总数一点不变）。
- **交给人看之前先跑**：不跑，「这节写完了吗」只能靠人肉重读回答，而重读一定会漏。
- **账要自洽才有人信**：报「清单 N 条／正文在 M 条」时，**分类计数与总数回核一次**（各类的行号相加＝总条数），分类行号与表格行数也要对齐——小计写错一次，这份账后面就没人敢拿它施工。
- **换入既有样板／重做稿：三个动作固定做**（顺序不能反）——① **先逐条 grep 承接锚**：上一节点名交给它的东西在新稿里在不在，缺的当场补（实测重做稿缺了上一节刚埋的「有重量」）② **再补最新口径**：样板／重做稿常常是**旧口径时期**做的，字数再好看也得按当下口径过一遍（实测一版样板 `她说`×9、一版重做稿 `她说`×12；最省的手法：删标签、让紧邻的动作自己站着）③ **报告差异**并把新稿的账写回骨架（旧行号作废，承接表的行号要一起更新）。
- **账里要有跨节冲突这一栏**：同一件东西／同一条设定在两节的写法并排核（「掉的不长回来」vs 后文「新长出来的羽毛」；上一节埋的「那片林子」vs 下一节写成「一片屋顶」）——**设定被后文推翻，量尺永远看不见**。只核引文与计数，核不出这类。

> 标过「已收口」的节照样要跑：账核对的对象是**骨架**（它不随稿子改而更新），它抓的正是前面几轮自己改出来的空洞。
