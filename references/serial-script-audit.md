# 连载口播稿审核（录制前）

> 适用：**一稿分多集**录／播的稿件（音频、视频口播、评书式连载、讲解系列）。稿件不是叙事小说，是讲解／画像／知识输出——审的不是「平不平」，是「能不能直接上麦」：能不能一口气读完、集与集之间会不会重、听众认不认得出谁是谁。
> 与小说稿的分工：小说看五行体检（`scripts/prose-metrics.py`）；这类稿看下面五把尺。

## 〇 触发与默认动作

- 用户只甩稿子、文件名带「审核」而没有一句话 → **默认按「能不能直接录」审**，别再问用途；收尾只留一个「改到什么程度」的问题。
- 审完必落报告（见 §4），原稿复制一份进同一目录，可追溯。

## 一 取文本与切集

1. `read_file` 先读一遍——它能自动抽取 docx 正文，够读够判断。
2. 要做脚本统计时，必须拿回**段落数组**（`read_file` 的行号会与空段合并，按行切集会错位）：

```python
import zipfile, re
xml = zipfile.ZipFile(path).read("word/document.xml").decode("utf-8")
paras = re.findall(r"<w:p[ >].*?</w:p>", xml, re.S)
texts = ["".join(re.findall(r"<w:t[^>]*>(.*?)</w:t>", p, re.S)) for p in paras]
texts = [t for t in texts if t.strip()]
```

一个段落常被拆成多个 run，必须 `"".join` 再拼，否则半句丢。
3. **按稿子自己的集头切集**（例：`^(\d)偏(\d)，`），别按标题层级猜——集头正则要拿稿子原文试一次，命中数＝集数才算对。

## 二 五把尺（全部要横向对照，逐集读看不见）

| 尺 | 怎么算 | 判什么 |
|:--|:--|:--|
| **集长** | 每集汉字数 `[\u4e00-\u9fff]` | 报 min–max 与差值；换算秒数（250 字/分钟）看落差不难听出来。要求等长时，短的那几集＝补写清单 |
| **段式** | 先定这一系列固定的段式（例：样子／特点／生活／优势／不足／关系／独白／注意力／一句话），逐集打勾出表 | 哪集缺哪段一眼看见；连载靠固定节拍让听众认路，缺一段就是断拍 |
| **逐句重复** | 每集按句切 `re.split(r"(?<=[。！？])", 集文本)`，完全相同句子按集归档 | 同一句出现在**相邻两集**＝硬伤（等于同一段听两遍） |
| **近重复** | 8 字窗 Jaccard 两两比，排序 | 看**离群**，不看绝对值：top1 与 top2 的落差 5 倍以上，那条才是真撞车 |
| **呼吸点** | 句长 ≥55 字／段落 >200 字／单句逗号 ≥4 个 | 出换气与断句清单；口播稿出现长句＝录的时候卡在那儿 |

另加两项非统计的：

- **名称／别名撞车**：把稿里所有别名、代号、称号抽成表人眼过一遍。同一个词给了两个对象＝听众串号（脚本查不出来）。**两种高发形态**：① 两个对象共用同一称号（一对概念的两边被起了同一个名字）；② 把上位名目下放当子类名（总类名借给了其中分项）。混用两套译名／两套体系时几乎必然撞车——先问一句「这些名字是同一套体系里的吗」。
- **重复意象**：相邻两集用同一个比喻或同一个收尾句式（例：「小太阳」「夜夜…」），耳朵会当成复制。

## 三 坑

- **段式检查用关键词 regex 会误判，必须回读原文再报。** 拿「感情／恋爱」兜「关系段」、拿「生活里／单位里」兜「生活段」，会把段内顺带一句判成整段存在——实测两集判反（脚本说有、原文没有）。**脚本只出候选，交付前逐集打开原文核一遍。**
- 相似度阈值没有通用绝对值：题材重叠天然有底噪（本例正常相邻集 ~0.01），判撞车的依据是离群与幅度。
- 模板句密度要**数但别劝全删**：小标题式的固定句是连载的骨架（听众靠它认路），要改的是每个小标题**下面的第一句**措辞——每集换一处，或每三集换一版。
- 讲「某套分类」的稿子，多数集没把分类词点出来就是教学目的落空：光有人格画像，听众学不到分类本身。把「每集固定点一次名」写进必须改。

## 四 交付形

报告落 `workspace/records/<日期>-<主题>/审核报告.md`，原稿同目录复制一份。四段：

1. **结论先说**：底子行不行、能不能直接录、有几类硬伤。
2. **必须改**：每条带**原文引文**＋可验证的量（相似度、字数、缺哪段）。不带引文的意见会被当成印象。
3. **建议改**：听感与教学效果（模板句、集长、呼吸点、缺总纲/收束）。
4. **核对依据**：命名出处、配对/结构表出处、脚本口径（说明是实算不是目测）。
5. **下一步**：给 A／B／C 三个颗粒度（只修硬伤／连建议一起改／用户自己改），别问「要不要审」。

## 五 改完怎么落盘（最小改动版／方案 A）

口径是「只修硬伤、不动结构」时：**原稿一个字不碰，另存 `<主题>-修订A.docx`**，同时出一份改动清单（改了几项、每项原→新、哪些故意没动）。

python-docx 改 docx 的两个保格式动作：

```python
import copy

def set_text(p, s):          # 改一段：文本进第一个 run，其余 run 删掉（格式沿用首个 run）
    p.runs[0].text = s
    for r in p.runs[1:]:
        r._element.getparent().remove(r._element)

def insert_after(p, s):      # 插一段：deepcopy 同款正文段挂到后面，自然继承样式
    el = copy.deepcopy(p._element)
    p._element.addnext(el)
    set_text(docx.text.paragraph.Paragraph(el, p._parent), s)
```

- **一段文本常被拆成多个 run**（数字、标点各占一个）：定位用整段 `p.text` 判，改动走 `set_text`；直接改 `runs[0].text` 会只改掉半句。
- **插段要拿同款正文段当模板** deepcopy——在标题段旁边插会继承标题样式。
- **集头／小标题改名也走 `set_text`**，别用全局替换：标题里含数字，通配替换会连带把正文改了。
- **改完必须重新抽取全文、重跑五把尺**：重复句归零、撞车消掉、缺段补齐、集长落在可接受区间。没回读＝没改完。

## 六 著作权与出处（审稿必看的一节）

- 先读 `docProps/core.xml`：`dc:creator`／`cp:lastModifiedBy`／`dcterms:created|modified`；再看 `docProps/app.xml` 的字数页数。
- **`customXml/item1.xml` 里常有参考文献壳而条目为空**——挂着 APA 样式却零出处，最容易让人误以为有引用。
- `dc:creator` 若是 `python-docx`，说明稿子是脚本生成的；`lastModifiedBy` 是最后动它的人。两者不同就要问清三件：谁写的、谁改的、能不能改／能不能商用。
- 理论类稿子另查 **理论著作人**（框架与命名来自谁）与 **译名版本**（同一概念不同译本叫法不同，混用即撞车来源）；片头、简介要署名。
- 这一节只摊事实，不替用户拍板——署名、授权、商用只有作者能定。
