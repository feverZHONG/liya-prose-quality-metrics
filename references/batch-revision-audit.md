# 批量修改后的回查与「逐节对表」

> **什么时候用**：稿子经过多轮脚本改写（并流／去重／标点／加厚／换人称），要确认某一轮没改坏；或用户说「换一个思路，从头开始修订」「看看有没有跟笔记和纪律冲突」。
> 配套：主流程见 SKILL.md §3「改」，量尺／扫雷／语气标点三件套在 SKILL.md 与项目文档。

---

## 一、先定位「哪一轮改坏的」

```bash
git log --oneline -- <file>          # 这一稿经历过哪些批次
git log -S'<整句台词>' -- <file>      # 哪一提交引入/删掉了这一句
```

`-S` 命中**出现次数的变化**——「引入」和「删除」都会命中，方向要用 `git show <rev>^:<path>` 与 `git show <rev>:<path>` 对比确认。

⚠️ 路径解析不一致：`git log -- <path>` 按**当前目录**解析，`git show <rev>:<path>` 按**仓库根**解析。在子目录里跑，前者要写相对当前目录的路径，后者要写仓库根相对路径，写错就是「path exists, but not ...」。

### 一补 · 回滚／保留哪一版：**别按单一探针计数排序**

**症状**：改坏之后想「退回干净的那一版」，于是按某个探针的**告警条数**挑最少的提交回滚——结果退回到**手写成果更少**的旧版，稿子比回滚前更差（用户判语：「**因为你又改回去了，比之前还差**」）。

**机制**：形态类探针**假阳性率高**。「一段里有 ≥2 组台词、其间夹描述」这种探针，会把**合规**写法（同一个人的话被动作断开——`「A。」描述，「B。」`）一并算进去；所以「告警少」往往只说明**探针够不着**，不说明**稿子好**。实测同一批提交里告警最少的旧版（11 处，多为误报）恰恰是**没经过手写重写**的那一版；而语言重写过、告警 30 处的那版，其中真问题只有 9 处且可逐条拆。

**两份量都要量**：

| 量 | 怎么量 | 为什么 |
|:--|:--|:--|
| **可信告警数** | 抽读 3–5 处告警，估假阳性率，按真问题折算 | 原始条数不可比：口径不同的探针、含误报的探针会把排序整个带偏 |
| **手写成果量** | 那一版里有没有：重写过的叙述语言／修掉的重复行／补过的账／定过型的段落 | 回滚丢掉的不是数字，是**已经写好的稿**——丢了要重写一遍 |

排序依据＝**可信告警数 ＋ 手写成果量**，不是原始告警数。

**默认动作：留在语言最好的那一版向前修**——把真伤列成单（位置｜原文｜伤形｜改法）逐条拆，**不要退回到数字看着干净的旧版**。回滚只用于「这一版整体方向已废」的情形。

**回滚前先对齐「这一版含哪几轮成果」**：`git log --oneline -- <path>` 逐提交读一遍提交信息，把「哪一版有手写重写／哪一版有批量脚本」标出来再挑；回滚后在提交信息里写明**丢掉了什么、留下了什么**，否则下一轮会把同一个判断重做一次（本类项目实测连错两次，第二次才把方向摆正）。

## 二、把那一轮的改动**全量**拉出来（不要按猜的句形 grep）

```python
import subprocess, difflib
REV, P = "<批次提交>", "<仓库根相对路径>"
old = subprocess.run(["git","-C","<repo>","show",f"{REV}^:{P}"],capture_output=True,text=True).stdout.split("\n")
new = subprocess.run(["git","-C","<repo>","show",f"{REV}:{P}"],capture_output=True,text=True).stdout.split("\n")
for tag,i1,i2,j1,j2 in difflib.SequenceMatcher(None, old, new, autojunk=False).get_opcodes():
    if tag == "equal": continue
    print(f"[{tag}] 旧L{i1+1} → 新L{j1+1}")
    for l in old[i1:i2]: print("  -", l[:100])
    for l in new[j1:j2]: print("  +", l[:100])
```

逐条判「成立／换坏」，**判定标准只有一条：把上一句读出来，这句接得上吗**。

**批次的典型伤形**（同一个病根——只看了「这句像不像」，没看「接不接得上」）：

| 伤形 | 例 |
|:---|:---|
| 应答换成跟上文无关的抽象问法 | 上一句是陈述「三十一张。」→ 回一句「你说的是哪一句？」 |
| 台词被剥掉引号、变成无引号叙述 | 「你怎么知道的？」→ `你怎么知道的？`（量尺随即把它算成叙述，对话占比／台词条数掉） |
| 归属写反 / 写重 | 她答的「没有。」→「他摇了一下头。」；「她说。她说。」连写两遍 |
| 归属悬空 | 「他没接话，点了一下头。**他说，没抬头。**」——他说后面没有话 |
| **归属删半截（吊尾）** | 「她说，手停在那儿。」→「**她，**手停在那儿。」——批量删「说」时把标签切剩一半；读者看到的是主语后面挂个逗号 |
| **台词尾标点连引号一起吃掉** | 批量把 `。」` 换成 `？」` 时写成 `q[:-1]+"？"`：`「多深。」` → `「多深。？`——收尾的 」 没了（实测全篇 17 处静默失配，扫雷随即报一片假阳性，因为台词被漏进了叙事段） |
| **两刀叠加成坏句** | 去说刀删掉归属 ＋ 并段刀把「台词段」与「叙述段」并成一行 →「「多久了？」不知道。阁下没说过。」（原文是两段：她问／叙述他从未说过）。**单看每一刀都成立，叠在一起才坏** |
| 同一批里口径不统一 | 一半写「阁下点了一下头」，一半写「他点了点头」 |
| **整段替换带走挂在那段上的账** | 用新段覆盖旧段时，旧段里挂的**身体账／物件回收／伏笔／时间标记**跟着一起没（实测：换收尾时把「收了一天的翅膀终于摊开」那半句带走，全篇身体轨迹断在倒数第二拍——量尺、扫雷、语气标点三项全不报） |
| **改了物件的来路，没同步取用路径** | 把道具的来处改到 A 处（「箱子里的铁丝」），下文取用时却还去 B 处（「从抽屉里翻出一小卷」）——两处并存就是硬矛盾。**定死一个新来路后，把依赖旧来路的动词句一遍** |
| **改了道具的存在状态，没同步依赖它的描写** | 开场的「灰在**灯**下浮着」默认屋里灯亮着，收尾又写「屋里没开灯」——同一件东西的**明暗／位置**（窗台上／端回桌上、虚掩／关严）也是全篇级的账，改一处就要清另一处 |

**一刀一查（多刀改同一批句子时的硬规矩）**：每一刀（去说／并段／标点／人称）落盘后**立刻**跑两道自检，不要攒到节末或全篇收尾——错会顺着后面的刀扩散（吊尾被并段刀并进更长的段之后，肉眼再也认不出来）：

```bash
# 1 引号配平：「 与 」 必须成对
python3 -c "import sys;s=open(sys.argv[1],encoding='utf-8').read();print(s.count('「')-s.count('」'))" <稿.md>
# 2 归属吊尾：引号收尾后吊着「她，」「阁下，」「他，」
grep -nE '」(她|阁下|他)，(？！)' <稿.md>   # 或直接跑 tone-punct-check.py（两项都已内置）
```

**回读「两刀都碰过的位置」**：把两轮的改动交集列出来逐行读上下文（本类项目的典型交集＝归属被删的那几行，正好也被并段刀动过）。判法仍是那一句：**把上一句读出来，这句接得上吗、还知道是谁在说吗**。

**纪律**：删归属时把标签**连标点一起删**（「她说，走过去」→「她走过去」）；改台词尾标点时只动引号**里面**那一个字符，绝不 `q[:-1]`（会连收尾的 」 一起吃）。

**替换整段之前先列「这一段挂了哪些账」**（身体账／物件回收／伏笔／回声／时间标记），替换完逐条搬回。整段覆盖是唯一会把账**静默**抹掉的改法——上面的三件套一个都不报，只有人读那本书的账时才会碰见。

**正文与账必须一致**：正文写进去了、普查单记的是「弃」→ 改判「采（改法）」；正文删了、普查记的是「采」→ 撤采。收口时正文与普查单各读一遍，两边的字要能对上（账实不符被点过一次：普查判弃的事件稿子里却写了）。

判完先落一份「真伤清单」（位置｜原文｜批次改后｜改回什么），再动正文。

## 三、逐节对表（正文 ↔ 笔记 ↔ 纪律）

- **一节一张表**：`位置｜笔记出处｜正文现状｜判定／改法`。出处＝大纲节点细单／本节加厚单／口径表。
- **判定三态**：✅ 一致｜⚠️ 冲突（改正文）｜📒 台账错（改笔记，不动正文）。
- **先查出处再判**：只读正文会把笔记明写的设计当成 bug（实测撤回过 5 条「看着像 bug、其实是设计」的误报——含一处「半句悬空」其实是为清零叙事否定式故意写的、一处回声句是笔记定的落点）。
- **口径项一次列全再扫**（人称／引号／标点／同一句 ≤2／段＝一拍），比想起来一条算一条快；对表顺手就把这些纪律扫了。
- **台账与正文会各自漂移**：某次修正只改了正文、加厚单里还记着旧句——对表时两边都读一次，把台账改回来（📒 不改正文）。

### 三补 · 多轮之后的重新对表（大纲／正文／方向，三样一起核）

触发：用户说「回到开头」「重新理一下」，或你自己发现**账上的数字与体感不符**。长活跑到「加厚 → 打磨 → 小样 → 外部评估」几轮以后，**大纲／正文／方向会各差一步**——**先停手对账，别接着写**。

| 样 | 核什么 | 怎么核 |
|:--|:--|:--|
| **大纲** | 逐节事件链与正文还是不是同一节 | 拿大纲的事件单对着正文读——**换过主轴／重做过的节最先错位**，对完顺手把大纲回填成正文的样子 |
| **正文** | **实测，不抄账** | 对**正文文件**跑量尺＋扫雷。账会漂：**样板／小样的数会被当成正文的数**（实测：样板已经到 11.5／21%，正文还停在 10.1／15%，而台账上记的是样板的——两边谁都没发现） |
| **方向** | 现行口径与旧口径哪一头作数 | 把打架的两条摆出来（例：「只改写法、不加事件」vs「整段剧情重做」），请用户定哪头 |

**小样／样板定稿就推回正文**，没推的在台账里明写「未推」——样板留在小样文件里等于成果蒸发，而且下一轮对表时正文与小样各说各话。

**逐节处置表**（回答「这一节该动多少」）：每节判一栏——**A 只改写法／B 剧情重做／C 不动**，三条判据：

1. 这一节的戏有没有**代价位**（做成这件事要付出什么／有没有可能失败）；
2. 开头与结尾的**关系或控制权**变没变；
3. 有没有「顺过头」的**外部反馈**（用户／外部评估／多视角读者踩过）。

**只给建议不代拍**：表＋判据交用户逐栏点头再动笔（B 类先出方案）。对表结果落一份「路线与逐节处置」文件，里面同时给出施工顺序与卡点。

## 四、改法与收工验证

**改法（一切都以「接得上」优先）**

| 症状 | 改法 |
|:---|:---|
| 短应答重复／换坏 | **回声式**——用上一句的触发词回问；仍嫌重就把其中一处改成动作 |
| 台词被剥引号 | 恢复引号，顺带核全篇同一句 ≤2 次（已满就换回声式） |
| 归属错 | 按「谁问谁答／谁做的动作」重排；多出来的一截动作句直接删 |
| 悬空归属 | 删后半截（「……。他说，没抬头。」→「……。」） |
| 口径不统一 | 按用户定的裁决统一（如叙述层人称），**统一前先数一遍剩余处数**，确认不误伤真正指第三方的那些 |

**收工四查（缺一不可）**
1. 病灶 grep 清零：`哪一?句`、`。他说[，。]`、`。她说。`、无引号短句行、`^#` 行吞没正文
2. 量尺 ＋ 扫雷 ＋ 语气标点三件套，**改前→改后**都留数
3. **多副本一致性**：工作稿与各分篇产物的 CJK 相加 == 工作稿正文 CJK；**待发布稿（draft）也算一份副本**——它的自校只在生成那一刻跑，正文后来改了它不会知道（实测落后两百多字），用 `scripts/draft-sync-check.py <定稿.md> <draft目录>` 核，不一致就重出
4. 逐条登记进项目文档（一份「修订登记」表：条目｜位置｜改前→改后｜依据），并在对话里只报结论与最要紧的几条——**别只在对话里说**

### 2·收口 · 通读 · 定稿门 · 审读分诊与收口

   - **量尺抓不到的那几类，定稿前必须真通读一遍**（逐行读完，一行不跳；`grep 关键词 ＋ 凭记忆` 不算通读，更不许这样报「已通读」）——清单含：重复动作／时间顺序／伏笔缺账／数字扎堆／撞句式／**空间错位／物理不可能／换人没交代／空转的答话**／**缝补句的时态**（撤掉旧句后补上的那一句读成「第二次发生」——补句要带时态锚或挪回原位）；**判为「不是洞」的也要写一句结论**（不写＝下轮被同一条再绊一次）。
     - **体检报红先分类：改前就红，还是本轮引入。** 脚本报 ❌／⚠️ 不等于这一刀捅坏的——`git show HEAD:<正文路径> > workspace/tmp/head.md`，同一个脚本跑两份、对行号与条目：**完全一致＝改前就有**，记账不硬修（要修另开一轮）；不一致的才是本轮引入、当场处理。汇报时把「这条改前就红」当**分类**说（附对跑证据），既不当借口，也不许说成「本轮修好的」。
     - **通读报出的账要分档处置**：单点、无歧义、不动结构的（字词／标点／位置错位／物理不通／撞句式／无主指代）＝**当场小修**（读原文→亲手写→逐处落→回读那几段→重跑归零项）；**拆段／并段、换人剪辑的信号、收尾取哪一版、某个数字是不是设计、整段重排归属语——一个字都不自己动**，连「为什么不动」写进稿边的账里交用户拍。⚠️ **「把重复的动作标签砍掉一半」也归结构类**：对话行必须带点描述是硬红线，减标签＝同段内换别的活＝整段重排，不是小修。
     - 清单、通读顺序、与普查单对账的做法 → `references/metrics-mechanics.md` §四。
   - **定稿门（最后一道，工具全绿也要走）**：通读时逐条核这几类**只在原文字里、尺子数不出**的东西——**物件有没有回收**（前面亮过的道具后面要交代）｜**身体账接不接得上**（同一处分量在一节里从未落地，结尾又用它抒情）｜**代称一致**｜**定指有没有落空**（写了「那位先生」前文就得有那一场；不补就改成不定指）｜**台词的时间指涉与人物关系的新旧对得上**（第一天来的人不能被说成老相识）｜**当日事件的先后顺序**（同一天里的「一点多→两点多→两点半→三点」要顺着走——工具不会算、审读的 child 也常不报，只有通读会发现原句被插成倒序）｜**同一拍的事写成了先后**（同一个时间点发生的事分散在两处，来路就散了）｜**承重物证的来源只能有一个**（头发上的水是洗澡水还是雨／他赤脚就没有鞋可脱——自己加的来路与既定设定打架时，物证会有两个来源；加来路前先把那条设定抄在手边，写完把鞋／水痕／伞／毛巾逐件问一遍「在这条设定下立得住吗」）｜**参考画面（原图／提示词）与大纲里的动词短语都当硬字段办**（姿态／手的位置／视线／背景物四条，写前抄进分幕，写完逐条回查「落在哪一句」；大纲里的「邀约」「等待」「拖到床里」同样要有一拍落地）——**对不上＝动线设计错了，不是图选错了**（实测：旧动线让「她下床去门口把人拖进来」，通篇没一处对上「跪坐床面、双臂前伸」；解法是把两者串成一拍：她跪着伸手→他自己走过来→她就势把人拉进床里，「拉」比「站地上拖」立得住）｜**文中自报的数量与分类**（「这三个字」其实是两个字、「六个字」其实五个、「第三张贴纸」前面只贴了两张、「甜的，咸的」两块其实同属一味——写的时候手上没在数，只有回头一个一个数才发现）｜**同一个人物的动作／口头禅在篇内重复**（同一个人「推了推眼镜」三次、同一句式「答得×」三连、「哦了一声」两回：把全篇 **4–6 字窗口的短语频次**拉一遍（逐段去标点后统计 n-gram，取出现 ≥3 的），先滤掉专名与必要重复（菜名／人名／主题词），剩下的按人物归堆——一人占 ≥3 ＝这条已经是他的招牌动作或口头禅。改法＝**换一处说法，不动内容**；只报数不判对错的项不在此列，动作标签的总量是承重的，别顺手砍半）。**结论（改了什么、哪几处判为「不是洞」）落进稿子旁边的账里**，再谈定稿／出发布稿。
   - **审读意见先分诊，别一股脑当成自己的锅**：陌生读者每轮换角度，翻出来的一批里既有**本轮改出来的**、也有**原稿就埋着的**——不分诊就会去回滚本来改对的地方。`bin/story triage <篇号> --list <引文清单>` → **旧疾／已修／新伤／无效** 四栏（无效＝两版都找不到＝引文核验失败，先回原文核，别急着信；改动已提交时工具自动退到 `HEAD~1` 当参照）。
     - 收口**看比例不看条数**（任务书封顶 N 条时，审读每轮都会报满）：**误报率上升** 或 **旧疾过半** ＝ 收口，剩下按单点小修走，别再加轮次。
     - 旧稿整轮回头改的完整工序（批次清单／收口记录／动作链编排／全篇同类扫／格式不单改）→ `references/retrofit-pass.md`。
     - **同一条被两轮以上重复提，就不该再判「非洞」**：**读者卡就是卡，设定上成立不解决问题**——改成**让读者不用算也能顺过去**的写法，别再写一遍理由（实测「裙摆高度」「光走了又走出光斑」被连提三轮，前两轮都判非洞放过）。
   - **审读是验收门，不是改稿的节拍器——不许改一点审一点**（阁下 2026-09-25 点名「改动不全面」）：把「**全篇同类扫 ＋ 通读发现 ＋ 审读报的**」合成**一批**一次落笔——同类要自己在全篇数（审读只报它点到的那一处），落完跑工具，**才**派审读。
     - **动笔前自问**：「**这一批还差什么没带？**」——同类扫清了吗？上一次改动的前后各段重读了吗？还是只盯着被点名那一行？
     - 呼应铁律 5（一节内的口径一次带走）——这条管「一次改动的批次」。

   - **门后还有一道：派一路陌生读者（独立审读）**——量尺＋归零项＋通读全过之后，**一路子代理当陌生读者**再读一遍全文（用户可能就一句「派一个小队，一个人就行」）。它拓出来的正是这五类里最难自查的那部分（实测已全绿的成品稿：道具前后状态矛盾——空杯被拿去喝出烫、配角凭空知道了价格、复盘把两位客人对调、一句本该是他说的话挂在了她名下）。任务书写死四样：① **只给文件路径＋作品前提（体裁／人称／哪些设定是真的），禁读大纲／改动单／前几轮评审记录／git 历史**——读了就从陌生读者变合规检查员，只会把你已知的规矩再核一遍；② **只读不改**，清单落 `scratch`（别落进作品目录，否则下一轮它就成了「内部档案」）；③ **「找不到就写无」**＋条数封顶（如 12）＋每条逐字引文带真实行号；④ 要它自报引文核验通过条数。回来**自己重跑同一引文断言**（自报「N/N 全中」不算验收），再分三层报（硬伤／读着别扭／存疑），**不采的连理由落档**。**审读不是一遍就够：审完之后只要又动过正文（加厚／改标点／搬段），就再派一路新读者重审**——实测第一轮 13 处清完、又做了加厚与语气标点，第二轮照样抓出 13 处，全是工具不报的形态：同一场戏被写成两个日期（「昨天」对「三天前」）、道具凭空移动（一块饼先进口袋、又留在吧台、又进纸袋）、状态互斥（「绷了一周」对「从掏出那笔那天起」）、器物媒介不搭（粉笔黑板上「用铅笔」画框）、字数自报（「区隔」写成「这三个字」）、动作紧接而被读成另一个人（「莉娅转过头。血族红瞳里的那点光……」）。⚠️ **新加的事件戏是硬伤高发区**——量尺与红线一处不报，只有独立读者读得出来（实测 12 条意见里 8 条出自新写的 840 字）；加戏之后审读是必走项，重点查新增段。

   - ⚠️ **改完之后的「验证轮」跟陌生读法相反：要把改动清单列给它。** 两种审读轮的差别写死：
     | 轮次 | 任务书 | 它抓什么 |
     |:--|:--|:--|
     | **陌生读法**（出问题用） | **禁读**大纲／改动单／前几轮评审／git 历史，只给路径＋作品前提 | 铺垫不够、指代无来处、读感塌陷——你真查不到的那类 |
     | **验证轮**（改完用） | **逐条列出这一轮改过哪里**（位置＋改法），要它判「已对上／仍对不上／改后带出新问题」三态 | **修一处带出的另一处**——实测就是它拓出了「箱子里的铁丝却去抽屉找」「报纸上的火烤痕迹没有火源」这两处新伤 |
     次序：**陌生读法出单 → 逐处改 → 验证轮核改动**。只跑前者，改动带出的新伤没人看；只跑后者，稿子本身的问题没人看。
